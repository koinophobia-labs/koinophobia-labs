## How I build

1. **Live the friction.** Start from a real workflow instead of a feature list.
2. **Define the boundary.** Decide what the product should do, what it must refuse, and what requires a human.
3. **Build the smallest useful loop.** Make the core action complete before expanding the surface.
4. **Pressure-test it.** Use regression suites, adversarial personas, state-integrity checks, and device or browser QA.
5. **Watch real use.** Treat confusion, abandonment, and unexpected behavior as product evidence.
6. **Refine or refuse.** Fix what improves the thesis; reject additions that only make the product look bigger.
7. **Ship with receipts.** Record the build, limitation, test, and next proof instead of calling unfinished work complete.
